# Taste skill v2 reruns

The design-taste-frontend skill ([Leonxlnx/taste-skill](https://github.com/Leonxlnx/taste-skill)) shipped v2. These runs repeat the With Taste Skill condition with v2.1.4 (`@6010f91a`). Each rerun replaces that model's earlier With Taste Skill entry in place: same group, same route, same card. The entry carries `skillVersion: "v2"`, which shows a small `v2` label on the card and "With Taste Skill v2" in the skill picker. Entries without the field are v1 runs, recorded in their own benchmark folders.

[provenance.json](provenance.json) records each session, [costs.json](costs.json) the token math, and the `*.source-sha256.json` files the original files before gallery adaptation.

## Shared setup

Every run starts from the same Next.js 16.3.8 / React 19.2.8 starter (`@eeeb008`, lockfile SHA-256 `ce550054…cb915`, unchanged by the runs) with the pinned skill copied into the agent's project skill folder. The prompt is the v1 With Taste Skill prompt with only the dev-server port changed. One prompt, no follow-up coaching, no orchestrator edits to the generated app. Generation happened outside the gallery checkout.

## GPT-6.1 Sol (`sol-6-1`)

**Harness change from v1.** The v1 run used the Codex desktop app (bundled CLI 0.160.0). This run used the Codex CLI 0.163.0 headless (`codex exec --json`), model `gpt-6.1-sol`, reasoning `xhigh`, `--dangerously-bypass-approvals-and-sandbox`, on macOS. HOME and CODEX_HOME were isolated and held only a copied `auth.json` and a benchmark config. Codex bundled skills, ChatGPT apps/connectors, plugins, tool suggestions and memories were disabled. Codex's built-in image generation and web tools were left at their defaults; the model used neither. The session's skill catalog listed only design-taste-frontend.

**Browser.** The config registered Playwright MCP 0.0.83 (isolated headless Chromium, 1440×960, screenshots allowed). In the scored session that browser was not visible to the model: at its first step it filtered its tool list for `browser|design|skill` and got an empty list, and the log has no browser MCP calls. It checked its pages with the skill's own headless-Chrome inspector (`scripts/inspect.mjs`, at 1440, 768 and 390 px) and looked at the results with Codex's `view_image`. That returned 70 images: four candidate photos and 66 inspector screenshots. The run operator reports an unscored preflight that saw only this skill and read a test canvas from pixels. Those preflight records were not in the transfer used for this import, so this README does not confirm them.

**Skill file change during the run.** At the end of the run, the skill's `scripts/lib/cdp.mjs` had an extra Chrome flag, `--use-mock-keychain` on macOS. Chrome in the isolated home couldn't reach the Keychain. The run operator reported this as an edit by Sol. The session log does not show it. The model's own `git status` at 17:32:03Z shows the file unmodified. The file's mtime is 17:42:33Z, while three inspector runs were in flight, and no tool call in the log writes it. The model then ran `git diff` on it at 17:47:35Z and never mentioned it. Who made the edit is unresolved. It changes the inspector's browser launch, not the generated app, and is not part of the gallery source.

**Session.** Started 16:21:27.617Z, finished 17:48:01.954Z on 2026-10-21 (5,194 s). That wall time includes network outages on the Mac: stream reconnects at 16:37Z and a wait for the network around 17:22–17:25Z. The model fetched its fonts (Google Fonts, Fontshare) and pictures (two public-domain images through the skill's asset script, two Unsplash photos through Lorem Picsum) and saved them into the project.

**What it made.** The model built one "Commonplace" landing page component and gave it five themes: grey and brass archive, mint and pink connection map, sand and cobalt Anton poster, monochrome-and-red workspace, and orange, sky blue and lime condensed poster. Each theme changes the hero, palette and type. All five share the same copy and sections: a working notes demo with search, filters, local saving and Markdown export, a features block, a collections gallery, pricing, FAQ and a large wordmark footer. The model's own summary is in [sol-6-1.design-taste.final.txt](sol-6-1.design-taste.final.txt).

**Cost.** API-equivalent $2.48 at OpenAI's Standard rates for `gpt-6.1-sol`, checked 2026-10-21 on [OpenAI's pricing page](https://developers.openai.com/api/docs/pricing). Short context (≤272K input tokens per request): $2.00 per million uncached input tokens, $0.10 cached input, $10.00 output. Long context (>272K): $4.00, $0.20 and $15.00. Usage: 9,050,765 input tokens, of which 8,749,824 were cached, plus 74,532 output tokens (18,448 of them reasoning), across 57 requests. Five requests went over 272K and are priced at the long-context rate, which adds $0.25. At short-context rates throughout, the run would cost $2.22. Codex ran on a ChatGPT sign-in, so this is an estimate, not a cash charge. Per-request tiers are in [costs.json](costs.json).

**Gallery adaptation.** `<html>`/`<body>` became nested divs and the global CSS is scoped by the gallery generator. Fonts and images moved under `/variants/with-taste-skill/sol-6-1/` with their paths updated. The header's design switcher is no longer rendered because the gallery has its own iteration navigation. The wordmark link points to the gallery route. The gallery renders the same `Landing` component the source's `/[version]` route renders.

**Gallery verification.** The original source ran on its own dev server (`next dev`, port 3304, Windows) next to the production gallery build. All five pages were captured at 1440×1000 and 390×844 from both. The first headings match in text, computed font, size, color and width. Every page returned HTTP 200, with no page errors, no failed requests and no horizontal overflow at 390 px. Full-page captures are the same height, and their pixels differ by a mean of under 0.4 per channel. The differences sit in the header: without the switcher, the nav links and the Start for free button move right. See [source overview](sol-6-1.source-overview.jpg) and [gallery overview](sol-6-1.gallery-overview.jpg). In the gallery, the note editor opened, saved a note to local storage, and search found it. This checks that the embed is faithful. It is not an aesthetic score. The complete Playwright suite passed (434 tests) against the final production build. That includes a check that only v2 entries show the card label and the "With Taste Skill v2" picker option, and mobile render checks for all five pages. The v1-only test for the old Sol theme toggle was removed along with that source.
